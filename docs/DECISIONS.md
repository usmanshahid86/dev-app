## V0.1 — trustworthy opportunity discovery

| #   | Decision                                                                                                                                                                                                        | Why                                                                                                                                                                                                                                                                                                                                                                                                               | Reversal cost                                                |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 24  | Discovery requests **20** results per Jevlin query (was 8); the adapter clamps `max_results` at `JEVLIN_MAX_RESULTS_LIMIT=20`                                                                                   | Probed live (docs/SEARCH-INTEGRATION.md): the fast tier returns 10 merged results for 8/10/20 at the same 3000-micro cost, so the V0 cap of 8 silently discarded results 9–10, contradicting broad-discovery intent; 25 made the router answer with no provider (`chosen: -1`). Nothing is truncated below what the router returns; provider composition and tiers are untouched (Search Experiment 2 owns those) | low (env)                                                    |
| 25  | An `ok: true` Jevlin envelope with `chosen: -1` and an empty merged list is raised as a retryable `no_provider_answer` failure                                                                                  | Recording it as a successful empty search would hide a router problem from the run record; observed once in the dogfood run                                                                                                                                                                                                                                                                                       | low                                                          |
| 26  | Evidence identity = canonical URL per project; discoveries are a separate table; the V0 `evidence.query_id/position/provider_meta` keep the **first** discovery for backward compatibility                      | Preserves every discovery path (the Search R&D need) without rewriting V0 rows or the V0 migration                                                                                                                                                                                                                                                                                                                | medium (two places describe the first discovery)             |
| 27  | Canonicalization is conservative (keeps scheme, path case, meaningful query params; strips only `utm_*`, `ref`, `fbclid`, `gclid`, `dclid`, `msclkid`, `mc_*`, `igshid`, `yclid`, `_hs*`, `ref_src`, `ref_url`) | Two documentation pages distinguished by a query parameter must stay distinct; under-merging is recoverable, over-merging is not                                                                                                                                                                                                                                                                                  | low                                                          |
| 28  | Source categories are rule-based only (host/path patterns, title as weak hint), with a stated confidence; no agent fallback                                                                                     | Deterministic and testable; `other` with low confidence is an honest answer. Category is descriptive, never a credibility score                                                                                                                                                                                                                                                                                   | low (agent classifier can be added behind the same function) |
| 29  | Corroboration = counts + templated sentence; signals and opportunities store it; no composite number anywhere                                                                                                   | The brief forbids fake precision; counts are verifiable by the user in the inspector                                                                                                                                                                                                                                                                                                                              | n/a                                                          |
| 30  | Consolidation is a second agent pass over **all** raw signals at once; programmatic guards: unknown ids dropped, one consolidated per raw, uncovered raws become standalone                                     | Cross-batch merging needs the whole set; guards make a bad merge harmless rather than destructive. Raw signals stay; clusters/opportunities cite consolidated only                                                                                                                                                                                                                                                | low                                                          |
| 31  | Page fetching is a provider boundary (`PageFetcher`) with `http` (Node fetch, manual redirects, dns.lookup pre-check, streaming byte cap, Readability over linkedom) and `fixture` implementations              | Keeps HTTP out of workflows; no browser automation; public HTML is enough for V0.1                                                                                                                                                                                                                                                                                                                                | low                                                          |
| 32  | Discovery never fetches pages; comparison/deep/validation fetch under per-run budgets 4/8/3 chosen by the agent (`selectSourcesForFetch`)                                                                       | Keeps discovery cheap and broad; spends page reads only where evidence has become important                                                                                                                                                                                                                                                                                                                       | low (env)                                                    |
| 33  | DNS rebinding is mitigated, not eliminated: every resolved address is checked, redirects re-checked, but the socket connects by hostname                                                                        | Pinning the checked IP requires a custom undici dispatcher; deferred and documented in docs/EVIDENCE-PIPELINE.md                                                                                                                                                                                                                                                                                                  | medium                                                       |
| 34  | Agents receive bounded **evidence packets** (first 3000 chars of a fetched page, else the snippet), not whole pages                                                                                             | Keeps investigation prompts bounded with 8+ fetched pages; `DEVAPP_PACKET_MAX_CHARS` is configurable                                                                                                                                                                                                                                                                                                              | low                                                          |
| 35  | Support level is computed from evidence state + excerpt verification; the agent's `supportStrength` is kept as a separate, visibly "agent-rated" field                                                          | Never trust an agent-generated quote merely because it references a valid evidence id                                                                                                                                                                                                                                                                                                                             | n/a                                                          |
| 36  | Unverifiable excerpts are stored with `verified: false` and the reason, not discarded                                                                                                                           | Auditable: the user can see what the agent claimed and why it failed validation                                                                                                                                                                                                                                                                                                                                   | n/a                                                          |
| 37  | One automatic retry per agent operation on retryable failures, counted on the run (`agentRetries`) and emitted as `agent_retry`                                                                                 | Malformed structured output is common enough to warrant one retry; a repair prompt is future work                                                                                                                                                                                                                                                                                                                 | low                                                          |
| 38  | `evidenceUsage` flags are derived at snapshot time from lineage + `evidence_viewed` events (no stored "ignored" score)                                                                                          | Missed-evidence preparation without an opaque metric                                                                                                                                                                                                                                                                                                                                                              | n/a                                                          |
| 39  | Post-migration backfill runs in `openDb()` after Drizzle's SQL migrations (idempotent)                                                                                                                          | Drizzle migrations are SQL-only; derived columns for V0 rows need code; tested V0 → V0.1                                                                                                                                                                                                                                                                                                                          | low                                                          |
| 40  | A run interrupted by process exit stays `running` until re-opened; the dogfood attempt 1 was marked `failed` by hand and its partial artifacts kept                                                             | No resumable runs in scope; honest record over silent cleanup. A startup sweep that marks stale `running` runs as `failed` is the obvious next fix                                                                                                                                                                                                                                                                | low                                                          |

## V0.1.1 — honest retrieval status

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Why                                                                                                                                                                                                                                                                                                       | Reversal cost |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| 41  | Three orthogonal signals on every investigation: `retrieval` (did this run's searches execute), `Finding.retrievalOrigin` (where the cited evidence was first found), `Finding.supportLevel` (how well it is verified)                                                                                                                                                                                                                                                              | DOGFOOD-02 attempt 1 showed that fetch state alone cannot say whether fresh research happened; the three questions have different answers                                                                                                                                                                 | n/a           |
| 42  | An investigation is `completed` only when its own retrieval executed in full; otherwise `partial` with results kept                                                                                                                                                                                                                                                                                                                                                                 | "Completed" must mean retrieval and synthesis both ran; partial results stay useful but visibly provisional                                                                                                                                                                                               | low           |
| 43  | Bounded retry/wait on retryable search failures: honour `retry_after_ms` (default 5 s), 1 retry per query, 90 s total wait per run; beyond the budget, remaining queries are `skipped` with `failure_code='retry_budget_exhausted'`                                                                                                                                                                                                                                                 | Converts short rate-limit windows into complete runs without unbounded waiting; skipped is distinguished from failed                                                                                                                                                                                      | low (env)     |
| 44  | Round-robin query scheduling across comparison candidates                                                                                                                                                                                                                                                                                                                                                                                                                           | Sequential per-candidate order made every partial run bias against the last candidate (attempt 4 lost candidate C entirely)                                                                                                                                                                               | n/a           |
| 45  | Inherited evidence remains eligible for page selection; origin never changes on rediscovery or fetch                                                                                                                                                                                                                                                                                                                                                                                | A source found earlier can legitimately be read and verified now; conflating origin with verification would hide that                                                                                                                                                                                     | n/a           |
| 46  | Pre-tracking rows read as `retrieval: null` / `retrievalOrigin: 'unknown'` and the UI/exports say so                                                                                                                                                                                                                                                                                                                                                                                | Backfilling a status we did not record would be invention                                                                                                                                                                                                                                                 | n/a           |
| 47  | Historical retrieval backfill (`npm run backfill:retrieval`, preview by default, `--apply` to write) derives `retrieval`, `retrievalNote`, `candidateRetrieval` and the `completed → partial` status change from persisted query rows plus `search_failed` events only; it never writes `failure_code` on old query rows, never touches runs/findings/evidence, skips investigations that already carry a status (idempotent) and records a `retrieval_backfilled` event per change | Review asked for derived status without invented metadata and with an audit trail; the five DOGFOOD-02 investigations were backfilled this way on 2026-10-16 (attempt 5 complete; attempts 2–4 partial; attempt 1 none). Finding `retrievalOrigin` for historical findings stays `unknown` (out of scope) | n/a           |
